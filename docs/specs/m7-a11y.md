# Spec: m7-a11y

Status: implemented · Milestone: M7 (security hardening) · Area: `src/.../vimma/ui/`,
`src/browser/themes/shared/vimma/`, `packages/vimma-core/src/{theme,statusbar}.mjs`

## User story

As a screen reader user, or someone who needs readable contrast or no motion, I can use Vimma's
own chrome (the status bar, the overlay, the pickers, panels, prompts, notices and pages) as well
as Firefox's: each part says what it is, focus lands in it when it opens and goes back when it
closes, it speaks when something happens and stays quiet otherwise, and its text reads in both a
dark and a light theme.

## What each component is

| Component                               | Role (name)                                                      | Focus                           |
| --------------------------------------- | ---------------------------------------------------------------- | ------------------------------- |
| Status bar                              | `status` ("Vimma status bar"), `aria-live=off`                   | never takes it; read on demand  |
| Mode and failed-search announcer        | polite live region inside the bar                                | -                               |
| `ctrl+b ?` overlay                      | modal `dialog` ("Key bindings"), `aria-modal`                    | the dialog; back to the opener  |
| Goto, workspace and add-on pickers      | modal `dialog` (title) around a `listbox`                        | the listbox; back to the opener |
| Picker rows                             | `option`, `aria-selected`, the listbox's `aria-activedescendant` | -                               |
| Empty picker or panel ("No add-ons", …) | `role=none` line that the list's `aria-describedby` names        | -                               |
| Side panel                              | `region` ("Side panel") around a `listbox` ("Tabs in …")         | the listbox; back to the opener |
| Bookmarks panel                         | `region` ("Bookmarks") around a `tree` of `treeitem`s            | the tree; back to the opener    |
| Bookmark rows                           | `aria-level`, `aria-expanded` on folders, `aria-selected`        | -                               |
| `:` command line                        | `combobox` ("Command line") with a `listbox` of completions      | the input; back to the opener   |
| Command line error                      | `alert`                                                          | -                               |
| Rename and text prompts                 | non-modal `dialog` named by its question                         | the input; back to the opener   |
| y/N questions                           | `alertdialog` named by the question                              | the input; back to the opener   |
| Notices                                 | polite `status` region; errors in an assertive `alert` region    | never takes it                  |
| Link hint labels                        | `aria-hidden` (the status bar says "hint mode")                  | -                               |
| Find                                    | Firefox's find bar; "Pattern not found: …" once it closes        | Firefox's                       |
| Start page                              | `main`, the logo an image named "Vimma"                          | -                               |
| about:vimma                             | `main`, each section a `region` named by its heading             | -                               |

"Back to the opener": where focus was when it opened, unless the selected tab changed (a row was
picked) or that element is gone; then the selected page. Panels give focus back only when focus
is in them or nowhere: a click into the page keeps it there.

## Decisions

1. **The status bar speaks rarely.** It is `role=status` with `aria-live=off`, so titles and URLs
   are read on demand (a screen reader's "read status bar") and never announced. A polite region
   says a mode once when it changes, except help, command and panel mode, whose focused UI says
   it already (and the way back from them is silent). Hint, visual and resize mode have no
   focused UI, so they and the way back are said. A failed search is said once, after the find
   bar closes. The logic is pure: core `statusAnnouncement`.
2. **aria-activedescendant on the focused list.** Pickers and panels used to focus the dialog or
   the panel box; the active row was then never announced. The list itself now takes focus
   (`tabIndex=-1`: by script only, keys come through VimmaHost).
3. **Notices through persistent live regions.** The popover is `aria-hidden`; its text goes to a
   polite or (errors: a refused URL, an add-on or bookmark failure) an assertive region that is
   always in the tree. The same text again while shown is not announced again.
4. **Readable text tokens.** Colour tokens stay as the palette gives them; text is drawn in
   `--vimma-fg-dim` and new `--vimma-text-*` tokens, which are the palette colour moved toward
   black or white in 5% steps until it reaches 4.5:1 on every surface (`--vimma-bg`,
   `--vimma-bg-dark`, `--vimma-statusbar-bg`, `--vimma-selection`). No text is dimmed with
   opacity. Typed hint letters are underlined instead of faded.
5. **No motion.** Nothing in Vimma's chrome animates or scrolls smoothly, so
   `prefers-reduced-motion` has nothing to turn off; a test keeps it so.

## Contrast (WCAG 2.x AA, 4.5:1), before → after

Tokyo Night (built in): `--vimma-fg-dim` 2.17–2.97:1 → `#9197b2`, ≥ 4.5:1 on every surface;
`--vimma-muted` as text (start page and about:vimma hints) 1.50–2.05:1 → `--vimma-fg-dim`;
`--vimma-cyan` on a selected row 4.26:1 → `--vimma-text-cyan` `#4da2af`; opacity-dimmed text
(picker and panel indices, hosts, hints) → `--vimma-fg-dim`. Every other text token passed.

A light theme (Catppuccin Latte, `tests/contract/theme/light.colors.toml`): every coloured text
token failed somewhere (yellow 1.70–2.31:1, accent 3.18–4.34:1, red 3.52–4.80:1); the
`--vimma-text-*` tokens pass on every surface. Hint labels and mode badges already passed in
both (their text is picked for contrast).

## Focus colour (WCAG 1.4.11 non-text contrast, 3:1)

Firefox draws its chrome focus rings in `--focus-outline-color`, which defaults to
`--color-accent-primary`, Firefox's own blue or violet. Next to the mint vimma palette it
clashed on three things: the focused pane's outline in a split (`content-area.css`,
`.split-view-panel.deck-selected > .browserContainer { outline: var(--focus-outline) }`), the
address bar's focus ring (`urlbar.css`, `--toolbar-field-border-color-focus`, which is
`--focus-outline-color` under Nova and half of it without), and the other chrome focus rings.

- **Token.** `--vimma-focus` is the accent, moved toward black or white in 5% steps until it
  reaches 3:1 on every surface a ring touches (`FOCUS_SURFACE_TOKENS`: the text surfaces and
  `--vimma-muted`, the pane gap split.css paints, seen at the outline's rounded corners). For
  a palette whose accent already passes, it is the accent.
- **Chrome.** `focus.css` (loaded by `ui/theme-host.mjs` into every window) sets
  `--focus-outline-color` and `--toolbar-field-border-color-focus` to `--vimma-focus` on
  `:root`, `!important` over an add-on theme's, and not under `prefers-contrast` or forced
  colours, where Firefox's high-contrast tokens stay. No upstream patch.
- **Not overridden:** `--color-accent-primary` (primary buttons, toggles, checkboxes, links in
  chrome panels). Those carry text on or in the accent over Firefox's own surfaces, whose
  colours the palette does not know, so its contrast could not be guaranteed.

| Palette          | Accent    | `--vimma-focus` | on bg / bg-dark / selection / muted | on the focused address bar |
| ---------------- | --------- | --------------- | ----------------------------------- | -------------------------- |
| vimma dark       | `#1bf587` | the accent      | 13.26 / 13.60 / 9.41 / 7.95         | 9.76 (`#2b2a33`)           |
| vimma light      | `#056a39` | `#056536`       | 6.53 / 5.91 / 5.73 / 3.20           | 7.19 (`#ffffff`)           |
| Tokyo Night      | `#7aa2f7` | the accent      | 6.79 / 7.29 / 5.33 / 3.55           | 5.63 (`#2b2a33`)           |
| Catppuccin Latte | `#1e66f5` | `#1852c4`       | 6.10 / 5.67 / 4.47 / 3.19           |                            |

vimma light's accent is 2.99:1 on its pane gap (`#a3b0a9`), so its focus colour is one step
darker. The address bar's figures are from `browser_vimma_focus_accent.js`, with Firefox's chrome
in the same scheme as the palette; a dark-only palette under a light Firefox chrome is not
covered (Tokyo Night's blue is 2.52:1 on white).

(Since changed: the vimma palette is vimma.dev's "Aqua Split" one, and its rows are now: vimma
dark, accent `#2cf5d2`, `--vimma-focus` the accent, 13.84 / 14.18 / 9.55 / 8.04, 10.19 on the
focused address bar; vimma light, accent `#006b5e`, `--vimma-focus` `#006659`, 6.34 / 5.78 /
5.52 / 3.14, 6.90 on the address bar. vimma light's accent is 2.93:1 on its pane gap (`#a0b3af`),
so its focus colour is still one step darker.)

**about: pages** (about:addons, about:preferences) are not covered: they are separate documents
with their own `--color-accent-primary` and in-content stylesheets. Doing it would need a
per-URL sheet injected into each privileged page and the same text-contrast question as above.
A follow-up.

### Focus rings in Vimma's UI

`focus.css` recolours only the rings Firefox's own CSS draws with `--focus-outline`. Vimma's
lists and dialogs had none of their own, so they fell through to the UA sheet's
`:focus-visible { outline: 1px auto }` (`layout/style/res/ua.css`). An `auto` outline ignores
`outline-color` and every custom property: Gecko paints it natively (`widget/Theme.cpp`,
`PaintAutoStyleOutline`) in the element's `accent-color`, by default the system accent, a blue
such as `rgb(58, 127, 209)`. So each focusable part of Vimma's UI sets its own ring:
`outline: 2px solid var(--vimma-focus, AccentColor)` on `:focus-visible`, inset (`-2px`) on a
list or dialog so its overflow does not clip it, `-1px` on an input with a border.

| Element (focused)                                   | Ring                                     |
| --------------------------------------------------- | ---------------------------------------- |
| Side panel's tab list (`#vimma-panel ul`), its box  | mint ring                                |
| Bookmarks tree (`#vimma-bookmarks ul`), its filter  | mint ring                                |
| Pickers' lists: `prefix+g`, `prefix+w`, `prefix+e`  | mint ring (and on the dialog if focused) |
| Help overlay dialog (`#vimma-help`), its `/` filter | mint ring (the filter's was a border)    |
| Command line, rename prompt, y/N question (`input`) | none, by decision (below)                |

A list's highlighted row (`--vimma-selection`) is not 3:1 against the panel in every palette, so
the lists keep the ring. The command line and the prompts have none: the line exists only while
its input has focus (it closes on focusout), as Vim's does, and the accent prompt in front of
the caret (`--vimma-text-accent`, 13.60:1 in vimma dark) marks it; `outline: none` also keeps
the native blue ring off it. (Since changed: in the "Aqua Split" vimma palette the rings above
are aqua, and the accent prompt is 14.18:1 in vimma dark.) Copy mode, hints and the status bar take no focus in the chrome
(copy mode's caret is in the page). about:vimma's buttons already used `--vimma-focus`.

## Tests

- `tests/browser/browser_vimma_a11y.js`: role, name and states of each component through
  `nsIAccessibilityService`; the focused active row; live region politeness; a focus-return test
  per overlay, picker, panel and prompt.
- `packages/vimma-core/test/a11y.test.mjs`: `statusAnnouncement`; every text token on every
  surface in Tokyo Night (built in and Omarchy) and the light theme.
- `packages/vimma-core/test/a11y.test.mjs` also checks `--vimma-focus` at 3:1 on every focus
  surface in every palette above, and that it is the accent wherever the accent passes.
- `tests/browser/browser_vimma_focus_accent.js`: the focused address bar's ring and the focused
  pane's outline (three-pane split) are `--vimma-focus` in vimma dark, vimma light and Tokyo
  Night, and follow a `[theme.colors] accent` override live.
- `tests/browser/browser_vimma_focus_rings.js`: in vimma dark, each focused part of Vimma's UI
  above draws a 2px solid ring in `--vimma-focus` (never `auto`, the native blue), and the
  command line, rename prompt and y/N question draw none, with a prompt at 3:1 or more.
- `tools/test/chrome-css.test.mjs`: the CSS draws text only in checked tokens, dims nothing with
  opacity, animates nothing.
